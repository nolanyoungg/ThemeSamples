The case for a
persistent workspace.

Useful agents need somewhere to keep their work. A field note on context, continuity, and a better second run.

In this field note

Continuity mattersArtifacts carry contextA boundary you can see

A conversation is a useful place to begin. It is not always a useful place to leave the work. As a project grows, the brief changes, references accumulate, and decisions become harder to recover from a long sequence of messages.

A workspace gives those things a shape. The current brief has a location. The sources have a folder. The draft has a version. The next task can begin by looking at what exists, rather than asking someone to explain it all again.

Continuity matters.

The second run is where an agent product starts to feel like a working environment. Does it know what the first run produced? Can it distinguish the latest instruction from an abandoned direction? Can a person return after a day away and understand where things stand?

Persistence alone does not answer these questions. Keeping everything forever is not the same as keeping the right things accessible. A useful workspace makes current context obvious and history recoverable without treating every old message as equally important.

The goal is not to remember more. It is to make the next useful step easier to find.

Artifacts carry context.

A research task might leave a brief, a source list, and a set of open questions. Those artifacts serve different purposes. The brief is a conclusion; the sources make it inspectable; the questions explain where uncertainty remains.

Separating them helps both people and agents. A new task can work from the brief while looking up evidence when needed. A reviewer can challenge a claim without searching through the entire run. A collaborator can see what still needs attention.

Good artifacts also make handoffs less fragile. The work is no longer trapped in the exact conversation that produced it.

A boundary you can see.

A workspace is also an access boundary. It should be clear which files an agent can read, where it can create drafts, and which actions require a person to review. Those decisions belong beside the work, where they are easy to understand.

Start with a narrow task and a small context set. Inspect the output. Add scope when there is a reason to do so. The same principle that makes a workspace understandable also makes its behavior easier to evaluate.

The ideal result is modest: the next run begins a little better informed, the next reviewer has a little less to reconstruct, and the useful parts of the work have somewhere to stay.
